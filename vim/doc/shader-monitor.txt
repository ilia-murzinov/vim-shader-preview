*shader-monitor.txt*	Preview GLSL with shader-monitor inside Vim


Author integration for the standalone tool in this repository.

==============================================================================

OVERVIEW ~

Starts `node server.mjs` in the repository checkout as a background |job|.
The server watches shaders on disk while the bundled web UI hot-reloads in the
browser (default URL http://127.0.0.1:3847/ ).

==============================================================================

INSTALLATION ~

Use the vim/ subdirectory as your runtime-path root.

  vim-plug (https://github.com/junegunn/vim-plug) ::

    call plug#begin()
    Plug 'ilia-murzinov/vim-shader-preview', { 'rtp': 'vim' }
    call plug#end()

  After |:PlugInstall|, run `npm install` once in the plugin checkout root
  (the directory that contains `server.mjs`, e.g. under
  `plugged/vim-shader-preview/`).

  Native pack: add a `start` package whose path is the `vim/` directory of
  the cloned repo, or symlink `vim/` into
  `pack/…/start/<name>/`.

  Help tags::

    :helptags ALL

  or |:helptags| the `vim/doc` directory under your clone.

MARKDOWN-PREVIEW STYLE ~

If you use |:MarkdownPreview|-style flows in other plugins, the trio below
mirrors that pattern for GLSL (compare markdown-preview.nvim: before the
Node job is stopped, the editor notifies the server — like `close_all_pages`
there — so connected browsers can run `window.close()`. Some browsers block
that for tabs opened via an external `open` / `xdg-open` command.)

*:ShaderPreview*
	Starts watching the **current buffer directory** (`%:p:h`), spawns the
	server if needed, and opens the UI (when |g:shader_monitor_auto_open| is
	on). If the server already watches that same directory, only the browser
	is opened again when |g:shader_monitor_preview_reopen_browser| is on.

*:ShaderPreviewStop*
	Same as |:ShaderMonitorStop|: stops the preview job. When
	|g:shader_monitor_close_browser_on_stop| is on (default), runs
	`POST /api/close-pages` on the preview origin first (requires `curl`).

*:ShaderPreviewToggle*
	Stops the server if it is running; otherwise runs |:ShaderPreview|.

Maps (define your own — these are the plugs)::

	nnoremap <silent> <leader>sv <Plug>(ShaderPreview)
	nnoremap <silent> <leader>sV <Plug>(ShaderPreviewStop)
	nnoremap <silent> <leader>st <Plug>(ShaderPreviewToggle)

	Set |g:shader_monitor_preview_default_mappings| to `1` for the same maps
	on `<Leader>` (`sv` / `sV` / `st`).

SETTINGS ~

|g:shader_monitor_port|
|g:shader_monitor_host|
|g:shader_monitor_auto_open|
|g:shader_monitor_stop_on_leave|
|g:shader_monitor_watch_dir|
|g:shader_monitor_project_root|
|g:shader_monitor_node_executable|
|g:shader_monitor_preview_reopen_browser|
|g:shader_monitor_preview_default_mappings|
|g:shader_monitor_open_new_window|
|g:shader_monitor_browser_cmd|
|g:shader_monitor_close_browser_on_stop|

Browser opening is handled by |shader_monitor#browser_open()| (|:ShaderMonitorOpen|
and preview flows when |g:shader_monitor_auto_open| or reopen is on).

					    *g:shader_monitor_open_new_window*
`g:shader_monitor_open_new_window`
	Default `1`. When set, tries to open the UI in a **new browser window**
	instead of reusing the frontmost window: on macOS uses `open -n` (new
	app instance; Safari/Chrome each follow their own rules). On Linux,
	tries Chrome/Chromium/Firefox with `--new-window` / `-new-window`, then
	falls back to `xdg-open`. Set to `0` for the previous “single `open` /
	xdg-open” behaviour.

					    *g:shader_monitor_browser_cmd*
`g:shader_monitor_browser_cmd`
	When non-empty, this shell command is run instead of the defaults. Use
	the literal `%URL%` where the URL should go (it is replaced with a
	shellescaped `http://…/`). Example: >
		let g:shader_monitor_browser_cmd =
		      \ 'open -na "Google Chrome" --args --new-window %URL%'
<

					    *g:shader_monitor_close_browser_on_stop*
`g:shader_monitor_close_browser_on_stop`
	Default `1`. When stopping the preview, the plugin sends
	`POST http://{host}:{port}/api/close-pages` before |jobstop()|, so the
	server can tell open UI tabs to close (WebSocket message). Set to `0`
	to skip that step. Requires `curl` in `$PATH` for the HTTP request.
